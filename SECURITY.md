# Security and threat model
Use OWASP ASVS/API guidance and STRIDE as design references, not claims of certification. Default deny, least privilege, MFA/passkeys mandatory for privileged accounts. Rotating sessions, secure HttpOnly cookies, CSRF/origin validation, CSP, parameterized queries, rate limits, TLS, secret manager, dependency and container scanning. Tenant ID from verified membership, never trusted client input. PostgreSQL RLS with non-owner non-bypass application role; composite tenant foreign keys and negative access tests. Staff scoped by branch. File uploads size/type limits and malware isolation. Audit restricted, immutable to ordinary app roles, externally retained; redact sensitive data.

## Financial threats and controls
Client price tampering -> server price snapshot and tax rules; spoofed webhooks -> provider signature and merchant/amount/currency checks, authoritative provider status; duplicate events -> unique provider identifiers and idempotency keys; concurrent refunds -> locks/atomic balance rules; cash deletion -> compensating entries and manager approval; fiscal timeout -> independent pending/unknown state and provider reconciliation before retry. Never store card PAN/CVV. Provider-hosted checkout preferred. SaaS billing separate from restaurant merchant settlement. QR token copying -> opaque revocable token, rate limits and optional staff confirmation for remote abuse; never grants admin access. Superadmin misuse -> time-limited support access, reason and audited approval. Subscription bypass -> server-side entitlement checks. Backups encrypted/offsite with restore test.

## Operational targets
MVP RPO <=15 min and RTO <=60 min, 99.9% availability target subject to tests/infrastructure. Incident playbook: contain, revoke, preserve evidence, restore, reconcile, notify as legally required. Data minimization, retention policy, export/deletion subject to fiscal retention and local law. No production personal data location decision before legal review.
