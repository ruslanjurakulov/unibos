# Logical database model
All tenant-owned records carry organization_id; branch-owned records additionally branch_id. Composite foreign keys enforce scope. UUID identifiers, UTC timestamps; display local time. Money in integer minor units with currency code; quantities NUMERIC and explicit units. No floating point financials.

Identity: users, sessions, organizations, branches, memberships, roles, permissions. Catalog: categories, products, price_versions, media. Operations: tables, qr_tokens, orders, order_items, order_events, kitchen_tickets. Money: payment_attempts, payments, refunds, fiscal_receipts, ledger_entries, cash_shifts, reconciliation_runs. Billing: plans, plan_versions, modules, subscriptions, entitlements, usage_events. Infra: webhooks, outbox_events, audit_logs, security_events. Future: ingredients, recipes, recipe_versions, stock_movements, suppliers, purchase_orders, expenses, loyalty.

Order snapshots retain price/name/tax at purchase. Separate order/payment/fiscal state machines. Unique provider event and transaction IDs within provider/merchant scope. Idempotency bound to tenant/action/request hash. Append-only balanced ledger entries; refunds reference original payments. Stock deductions on preparation, waste/cancel as explicit movement. Migration expand/contract with backups, staging and rollback/forward repair plan. Schema and constraints require implementation review.

## P2 implemented subset
Global identity tables are isolated behind unibos_auth; organization-root ids and tenant-owned branch/membership/audit rows use restricted unibos_app with FORCE RLS and composite constraints. Versioned local migrations, real negative tests and the boundary between implemented schema and future logical entities are documented in docs/P2_SECURITY.md. Financial/catalog/subscription tables above remain plans, not created schema.
