# UniBOS website and interface previews

The public marketing site follows the owner's eight JPG reference pages: a cinematic restaurant hero with a laptop dashboard, QR-menu phone and NFC stand; a solutions overview; QR-menu demo; restaurant dashboard demo; Super Admin demo; pricing; about; and contact. Public routes include `/`, `/solutions`, `/demo`, `/demo/guest`, `/demo/dashboard`, `/demo/super-admin`, `/pricing`, `/about`, `/security`, `/investors`, `/faq` and `/contact`. Marketing and demo surfaces support Uzbek, Russian and English, a compact mobile navigation and persisted light/dark appearance. The approved central-bar U mark and self-hosted Playfair Display and Inter fonts are used.

Dashboard and Super Admin previews use a separate Global Corporate interface. All dashboard figures, restaurant names, plan labels and order mix are illustrative and are explicitly marked as demo data. The solutions and homepage module cards distinguish interactive demos, API foundations, visual samples and planned modules. Pricing repeats the reference mockup's monthly figures only under a prominent demo/non-production label; annual amounts stay unpublished until approved. Contact is a visual preview with no text inputs or form submission, so it neither collects, sends nor stores visitor details.

The `/demo` hub links to existing demos without duplicating their logic. `/security` distinguishes local code/test evidence from controls not connected or not completed for production. `/investors` describes the product direction and validation plan without unverified financial or traction claims. `/faq` answers product availability and preview-boundary questions.

The guest-menu demo supports category filtering and a local-only sample cart. It never submits an order or payment. The authenticated Business Workspace at `/dashboard` remains a separate, security-scoped P2 surface: it reads the organization/branch API only after verifying identity and MFA. With no configured API, account and organization actions stay disabled and the UI displays a safe offline state. Sign-in and sign-up preserve enrollment and sign-in while offering an explicit existing-factor re-verification path after MFA assurance expires.

The local API proxy uses `UNIBOS_API_ORIGIN`, defaulting to `http://127.0.0.1:3001` outside Vercel. For local authentication, open the site at `http://127.0.0.1:3000`; that exact origin is present in the generated local API trusted-origin configuration. If a Vercel preview has no configured backend, same-origin API routes return a fixed 503 and the sign-in form stays disabled; credentials are not collected. Production requires an explicitly configured secure API origin and verified TLS, plus reviewed email verification and delivery before signup is enabled.

Run the website workspace `dev`, `build`, `start` and `typecheck` scripts from the repository root. Development binds to loopback by default; the preview server also binds to loopback. The build uses webpack explicitly. Font binaries are self-hosted and covered by the OFL notices in `assets/brand/`.

The website workspace declares its own TypeScript and Node type development dependencies so Vercel can type-check it when building from `apps/website` as the monorepo root directory. Vercel project build settings use Node 24.x, matching the repository engine range.

Security headers are a local baseline; CSP allows Next's inline bootstrap/style content. Production needs a reviewed nonce/hash policy and HTTPS/HSTS configuration. `robots` noindex is a crawler hint, not access control. See `docs/DESIGN_SYSTEM.md` for visual and content rules.
